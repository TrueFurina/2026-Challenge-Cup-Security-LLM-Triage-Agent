## 第一部分：痛点与背景（3 页）

### P1 封面
- 标题：**基于 LLM 与确定性规则混合架构的安全事件研判智能体**
- 副标题：安全事件初步研判与误报剔除智能体
- 团队信息 + 赛题编号（XH-202614 / XH-202609）

### P2 安全运营的三大痛点
- 告警泛滥：海量告警淹没真实攻击，分析师疲劳
- 误报率高：规则引擎误报多，人工核对成本高
- 大模型直接用于研判：成本高、慢、有幻觉

### P3 我们怎么做（方案一句话）
- **规则先筛、LLM 深判、人工兜底**——确定性预筛 + LLM 决策核心 + 置信度门控 + HITL 闭环

---

## 第二部分：方案与架构（4 页）

### P4 整体架构图
- 六层架构：输入 → ① 确定性预筛 → ② LLM 深度研判 → ③ 多 Agent 协作 → ④ 闭环处置 → ⑤ 审计
- 配图建议：使用 `docs/ARCHITECTURE.md` 的架构图

### P5 确定性预筛器（阶段 1）
- 三态分流：AUTO_CLOSE（误报自动关闭）/ AUTO_ESCALATE（直接定级）/ NEED_LLM（深判）
- 规则可配置（`data/prefilter_rules.json`，7 攻击规则 + 4 误报规则）
- 效果：**LLM 调用节省率 70%**

### P6 置信度门控 + HITL（阶段 2）
- 置信度数值化：high 0.9 / medium 0.7 / low 0.5
- 低置信 → 待人工复核，不自动处置
- 复核反馈回写（review_feedback），供误报记忆使用

### P7 多 Agent 协作 + 知识库（阶段 3-4）
- Triage → Hunt → Respond → Report 顺序协作
- RAG 知识库：21 条含 ATT&CK/CVE/预案，prompt 注入 grounding 依据

## 第三部分：核心创新（3 页）

### P8 创新 1：预筛+LLM 混合架构
- 市面上多数项目单模型全量研判 → 我们规则先筛
- 明确攻击/误报毫秒级裁决，不确定才给 LLM

### P9 创新 2-3：置信门控 + 误报记忆
- 置信度门控：低置信不自动处置（HITL）
- 误报记忆：相似历史注入 prompt，同类误报不重复出现

### P10 创新 4-5：多 Agent + 审计账本
- 多 Agent 顺序协作体现"自主决策"
- Investigation Ledger：全链路证据链可回放、可导出
