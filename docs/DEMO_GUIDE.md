> **版本**：v2.0（加入 AI 研判展示要点 / LLM vs 规则对比）

## 演示目标

不要讲成通用聊天工具，而要明确讲成：

**基于 AI+安全大模型平台的安全事件初步研判与误报剔除智能体**

核心叙事（一句话）：

> "这是一个以 LLM 为决策核心的安全智能体——它能调用工具、检索知识、综合证据推理出风险等级和误报判断，LLM 不可用时自动回退规则引擎，永不宕机。"

## 演示时建议强调的点

### 强调 AI 决策（本次升级核心）

旧版：硬编码规则数关键词 → 低智能
新版：**LLM 综合 5 项工具观测 + 知识库推理** → 真智能

演示话术：
> "过去我们用 15 个关键词硬编码判断风险。现在我们让 LLM 综合资产画像、日志、情报、历史告警、误报线索和知识库做推理——这是从'规则匹配'到'智能推理'的升级。"

### 强调工具能力

内置关键工具：IP信誉 / 资产重要性 / 历史告警 / 日志 / 误报检查。

### 强调结构化输出

系统输出：风险等级 / 风险评分 / 事件类型 / 误报判断 / 证据链 / 工具观测 / 处置建议。

### 强调分阶段 Agent

- `Monitor Agent` → `Context Agent` → `Triage Agent` → `Report Agent`
- 向评委解释：不是"单次问答"，是"有角色分工的智能体流程"

### 强调 fail-open（可靠性）

> "LLM 不可用、超时、解析失败，系统都自动回退规则引擎，绝不崩溃——这是生产级智能体的工程要求。"

## 推荐演示话术（升级版）

"本系统聚焦安全事件初步研判与误报剔除场景。事件进入系统后，先由 Monitor Agent 接收并识别场景，再由 Context Agent 查询资产、日志、情报和历史告警，随后 **Triage Agent 交由 LLM 综合全部证据完成风险定级与误报判断**，LLM 不可用时自动回退规则引擎，最后由 Report Agent 输出结构化研判结论与处置建议，并支持报告导出和全量评测。"
