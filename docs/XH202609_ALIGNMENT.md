## 2. 三大核心特性 vs 项目现状

命题书明确要求智能体具备三大特性：

### （一）自主任务理解能力
> 理解自然语言、结构化文件、**压缩文件、接口文档**等多形式任务目标，自动解析需求并生成可操作执行计划。

- ✅ 现有：告警事件 intake（内置/上传/日志解析）、自然语言研判、计划生成（planner.py）。
- ❌ 缺口：**压缩文件解析、接口文档解析**未实现；任务理解限于"安全事件"而非"开放式安全任务"。
- 自评档位：8–12 分（能理解常见任务，但复杂/多模态/开放式不足）。

### （二）多场景自主决策与执行能力
> 适应**渗透测试、应急响应、漏洞挖掘、逆向分析**等场景，具备态势分析→目标设定→任务规划→实时策略动态调整的闭环。

- ✅ 现有：安全事件研判 + 误报剔除 = **「应急响应 / 威胁感知」子集**；有 Hunt/Respond/Report Agent。
- ❌ 缺口：仅覆盖应急响应一个子集；**渗透测试、漏洞挖掘、逆向分析场景缺失**；"响应处置"偏轻（Respond Agent 未做真实处置动作）。
- 自评档位：8–12 分（单场景深，多场景未覆盖）。

### （三）运行鲁棒性与决策可靠性
> 决策可解释、可审计，关键行动有依据；对抗干扰稳定；行为可复现。

- ✅ 现有（**强项**）：Investigation Ledger 全证据链、置信度门控、规则回退 fail-open、误报记忆、RAG 降幻觉、评测可复现（90% 通过率）。
- 自评档位：17–20 分（可解释性设计完善，可追溯可复现）。

## 5. 决赛工程约束（提前准备，非现在做）

- 模型 API 必须是**国内备案通过的大模型**（当前用 DeepSeek ✅，符合）；需向主办方**提前报备**并经 AI 安全网关接入。
- 智能体需在**指定受控环境**部署运行 → 部署必须可容器化/一键起。
- 人机协同实战占 60% 客观分 → Web 大屏的"人审(HITL)回写"能力正好契合"3 人+Agent"协同形态，是加分点。
