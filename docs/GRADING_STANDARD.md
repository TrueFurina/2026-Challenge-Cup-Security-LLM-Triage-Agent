# 风险分级标准（单一真值）

> **文档定位**：本项目**唯一**的分级与分类判据来源。提示词（`ai/triage.py` 的 `TRIAGE_SYSTEM_PROMPT`）、
> 规则兜底引擎（`_TYPE_BASE_SCORE`）、预筛规则（`data/prefilter_rules.json`）、评测期望值
> （`data/evaluation_cases.json`）**四方必须与本文件一致**。出现分歧时，以本文件为准并同步修改其余三方。
>
> **版本**：v1.0（2026-09-26）
> **为什么需要这份文档**：此前「凭据转储」在提示词里是 critical、在评测集里是 high；
> 「恶意脚本执行」同类手法出现 critical/high 两档且无成文依据。判据不成文 → 必然漂移。

---

## 0. 一句话原则

**分级看「行为性质与损害程度」，不看「告警来源的 severity」。**
传感器给的 severity 只是输入证据之一，不是定级结论。

---

## 1. 风险等级判据（四档）

| 等级 | 判据（满足任一即成立） | SOC 对应动作 |
|---|---|---|
| **critical** | ① **不可逆损害已发生或正在发生**：勒索加密、凭据已被转储、已确认的大批量数据外泄、WebShell 已落地可交互；<br>② **高价值资产（域控 / 数据库 / 核心业务系统）上确认的攻击行为**；<br>③ **无用户交互前提的远程或自动执行链**（网络侧直接下发并执行的解释器命令、远程服务创建后执行） | 立即启动应急响应（P1），保全证据 |
| **high** | 攻击链**已确认启动但尚未确认造成损害**：需用户交互触发的执行链（钓鱼文档打开后 spawn 脚本解释器）、恶意载荷投递、横向移动准备、C2 信标外联、高频或成功的认证暴力破解、有业务掩体的批量外传 | 当日处置（P2） |
| **medium** | **可疑但尚未证实为攻击**：孤立未知外联、低价值资产上的可疑登录、无明确恶意特征的异常行为 | 排期复核（P3） |
| **low** | **有合理解释的正常活动**：白名单资产、维护窗口内、基线内例行运维、有审计留痕的合法运维登录 | 记录留痕，不处置 |

**关键澄清**：`critical` 的判据 ③ 是**「无用户交互」**，不是「跑在终端还是服务器」。钓鱼链因为需要受害者打开文档，攻击者尚未证明具备稳定控制能力，故记 `high`；
不经用户交互直接下发的执行链说明攻击者已在网络内具备活跃控制能力，故记 `critical`。

## 2. 事件类型分类标准

按**攻击链所处阶段**与**手法家族**划分，共 11 类（取值域即 `JSON_CONTRACT.event_type`）：

| 事件类型 | 判据 | 基线分 |
|---|---|---|
| 勒索软件加密 | 出现加密后缀、勒索信、批量文件加密行为 | 82 |
| 凭据转储 | lsass 访问 / mimikatz / sekurlsa / procdump 转储 / 凭据枚举 | 82 |
| WebShell 攻击 | Web 目录落地脚本、`?cmd=` 参数执行、webshell 特征流量 | 82 |
| 恶意脚本执行 | 脚本解释器**实际运行**（powershell/cscript/wscript）并伴随下载执行、编码命令、Bypass、反弹 shell | 72 |
| **Web 漏洞利用** | 服务端利用特征：注入（union select / sqli）、反序列化、目录穿越、命令注入——**已进入利用阶段**才归此类 | 70 |
| 恶意载荷投递 | 载荷**尚未执行**（邮件/网关拦截、附件未打开、仅落地） | 66 |
| 横向移动前置 | 管理共享（admin$/ipc$）访问、远程服务创建（PsExec/WMIC）、IPC 连接 | 62 |
| 数据渗出 | 批量导出、全表查询外传、上传外部对象存储 | 68 |
| 异常外联 | C2 信标、已知恶意情报命中、可疑周期性外联 | 55 |
| 异常登录 | 认证失败聚集、暴力破解、异常时段/异地登录、跳板跳转 | 45 |
| 通用异常行为 | 无法归入上述各类的可疑行为 | 40 |
| 误报 | `is_false_positive=true` 时强制取值（代码强制，见第 4 节） | — |

> **注（第二垂类）**：`Web 漏洞利用` 是「Web 漏洞利用研判」场景的主类型。
> 扫描探测类行为（nmap/openvas 等）**不单列为攻击类型**——扫描本身不是攻击，
> 仅当出现利用证据时才按 `Web 漏洞利用` 归类；白名单内的例行扫描按误报处理。

### 2.1 边界判据（高频误判点）

**① 恶意载荷投递 vs 恶意脚本执行 —— 按阶段，不按载体**
- 仍在**投递阶段**（邮件或网关**拦截**、附件尚未打开、仅落地未执行）→ `恶意载荷投递`
- 已进入**执行阶段**（文档已打开并触发脚本解释器**实际运行**：spawn wscript、shellexecute、downloadstring、执行编码命令）→ `恶意脚本执行`
- 两类证据同时存在时，**以「已发生执行」为准**。

**② 横向移动前置 vs 正常运维 —— 按动作性质，不按工具名**
- 访问/连接**管理共享**（admin$、ipc$、Event 5140/5145 且来源为远程）→ `横向移动前置` / high
- 仅**本机只读列举**共享或目录清单（net view、列举、查询）且上下文标注例行核查 → 属正常运维，按**误报**处理
- 仅凭工具名 `net.exe`、出现「共享」字样、或资产为域控 → **均不足以**判定横向移动

**③ 数据渗出 —— 按有无业务掩体**
- 有变更单掩护的批量外传 → `数据渗出` / **high**
- 无变更单的大规模外传 → `数据渗出` / **critical**

**④ 异常登录 —— 按是否审计留痕 + 失败是否聚集**
- 堡垒机/跳板机/运维审计系统记录的成功登录与网段跳转 → `异常登录` / **low**，**不判误报**
  （仍是需留痕关注的低风险行为，与「例行备份」这类无关注价值的活动区别对待）
- 认证失败**聚集**（暴力破解/凭证填充，含次数特征）或**异常来源的成功登录** → `异常登录` / **high**
- **单次**失败登录、无聚集、无成功迹象，但目标为高价值资产（财务系统、域控、核心业务库）
  → `异常登录` / **medium**（真实探测尝试，资产价值抬升一档；普通终端同行为则 low）

---

## 3. 分级与误报的关系

- 变更单、白名单、维护窗口**只能作为降低误报判定的依据**（`is_false_positive` 可判 `true`）；
  对**已确认属攻击性质**的行为，**不得**据其把风险等级压到 `medium` 以下。
- 判定为误报时：`risk_level` 取 `low`，`risk_score` ≤ 20。

---

## 4. 误报字段契约（代码强制）

`is_false_positive=true` → `event_type` 必须为「误报」、`risk_level` 必须为 `low`、`risk_score` ≤ 20。
该规则由 `ai/triage.py` 的 `_normalize_payload()` **强制执行**（不依赖模型自觉遵守提示词）。

## 7. 已知的判断分歧（保留可推翻）

以下为**判断而非事实**，如评审或实战给出更强依据，应优先采纳并同步四方：

1. **「凭据转储」定为 critical 而非 high**：理由是凭据一旦转储即需全域轮换（不可逆运维成本），
   且为勒索/横向的直接前驱。部分厂商默认给 high。本项目选择更保守（更严）的一档。
2. **「无用户交互」作为 critical 判据**：理由是不经交互的执行链意味着攻击者已具备活跃控制能力。
3. **「堡垒机合法登录」记 low 而非误报**：理由是审计留痕路径仍需关注，
   直接判误报会掩盖「合法凭据被滥用」这一真实风险场景。
