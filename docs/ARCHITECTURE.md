# 项目架构

> **版本**：v3.0（2026-08-10，全部阶段 1-9 已完成，目标架构已实现）

## 架构概览

本项目围绕 `安全事件初步研判 + 误报剔除` 场景，采用清晰的模块化结构。核心架构从「硬编码规则研判」升级为「**AI 优先研判 + 确定性规则兜底 + 多 Agent 协作 + 全链路审计**」。

## AI 研判核心链路（★ 决策引擎）

```
事件 + 5项工具观测 + 知识库 + 计划 + 历史记忆
              ↓
   ai.triage.triage_event()
              ├─ 构建中文研判 Prompt（SOC专家系统提示词）
              ├─ 事件详情 + 评分标准(0-100) + JSON契约 + few-shot
              ├─ 知识注入: ATT&CK/CVE 依据 + 历史研判记忆 ★阶段4/6
              ├─ ai_chat_json(temperature=0.1)  ← 低温度确保一致性
              ├─ 防御性解析（每个字段校验+默认值）
              ├─ 置信度数值化 (high 0.9 / medium 0.7 / low 0.5) ★阶段2
              ├─ 成功 → 返回结构化裁决
              └─ 失败 → _heuristic_fallback() 规则引擎兜底
```

## 四模块结构（底层）

1. **任务入口模块** — 接收样例事件 / 上传 JSON / 日志文本，统一转换为内部 `SecurityEvent`
2. **确定性预筛 + 智能体编排** — 规则先筛分流，LLM 深判 + 后处理
3. **知识与数据模块** — RAG 风格知识检索（21 条含 ATT&CK/CVE）+ 资产/日志/情报/历史告警
4. **工具执行模块** — 上下文查询 + AI 研判 + 狩猎 + 预案/工单/动作模拟

## 分阶段 Agent（多 Agent 协作层）

阶段 3 起升级为真正多 Agent 顺序协作（非仅展示层）：

| Agent | 职责 | 使用工具 |
|-------|------|---------|
| **TriageAgent** | 事件分类、风险定级、误报剔除 | asset/log/intel/history/fp_check + LLM 研判 |
| **HuntAgent** | 威胁狩猎、情报关联 | ioc_search, intel_lookup |
| **RespondAgent** | 处置建议 | playbook, ticket, isolation |
| **ReportAgent** | 汇总报告 | — |

## 主要数据流

1. 用户从 CLI 或 Web 选择事件，或上传内容
2. 入口模块将输入转换成统一事件对象
3. **确定性预筛器分流**：明确误报/攻击直接裁决（不调 LLM），不确定进入深判
4. 编排模块生成计划步骤，检索知识（含 ATT&CK/CVE）与相似历史记忆
5. 工具模块执行查询
6. **AI 模块完成核心研判（LLM 推理 + 置信度门控），不可用时规则引擎兜底**
7. 后处理补充预案 / 工单 / 动作模拟（低置信不自动开工单）
8. 全链路写入 Ledger 审计 + 误报记忆持久化
9. Web 大屏展示（决策可视化/三模式对比/审计回放）并支持导出

## 关键设计原则

| 原则 | 说明 |
|------|------|
| **AI 优先** | LLM 是决策核心，非事后总结 |
| **规则先筛** | 确定性预筛分流，LLM 只处理不确定事件（节省 70% 调用） |
| **Fail-open** | AI 不可用时规则引擎兜底，永不崩溃 |
| **防御性解析** | LLM 输出每个字段都校验，非法值回退默认 |
| **置信度门控** | 低置信不自动处置，人工复核（HITL） |
| **可审计** | Ledger 全链路记录 + Web 回放 |
| **可评测** | 三模式对比 + 混淆矩阵 + 成本估算 |
