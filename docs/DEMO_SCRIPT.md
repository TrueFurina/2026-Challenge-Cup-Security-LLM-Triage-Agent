## 各环节详细脚本

### 第一节（0:00-0:30）：痛点开场

**讲解词**：
> 各位评委好。今天演示的是一套基于大模型的安全事件研判与误报剔除智能体。安全运营最大的痛点是告警泛滥——大量误报淹没了真实攻击，分析师每天要人工核对数百条告警。我们的方案是：用 LLM 作为核心决策引擎，配合确定性预筛、置信度门控和多阶段 Agent 协作，形成一套"规则先筛、AI 深判、人工兜底"的完整闭环。

**操作**：打开 `http://127.0.0.1:8080`，展示深色科技风大屏首页，指向顶部指标卡。

---

### 第二节（0:30-1:30）：方案讲解

**讲解词**：
> 我们的架构是六层：事件输入 → ① 确定性预筛（毫秒级三态分流）→ ② LLM 深度研判（置信度门控 + 误报记忆注入）→ ③ 多 Agent 协作（Triage → Hunt → Respond → Report）→ ④ 闭环处置 + 审计 → ⑤ 知识检索 + 接地 → ⑥ MCP 工具生态暴露。

> 核心创新是"预筛 + LLM 混合架构"：明确误报/明确攻击毫秒级裁决（不调 LLM），只有不确定事件才走 LLM 深度研判。实测 **节省 70% LLM 调用**。

**操作**：指向首页"四模块链路" + "预筛分流统计"指标卡。

---

### 第三节（1:30-3:00）：案例 1——攻击（EVENT-001）

**讲解词**：
> 第一个案例：域控服务器遭到 PowerShell 编码命令攻击。注意左侧事件列表中它的严重性标记为高危。

**操作**：
1. 点击事件列表中的 **EVENT-001（域控服务器异常 PowerShell 连接）**
2. 观察结果区：
   - **AI 决策可视化**：risk_score 数值条（85/100）、置信度徽章（high 0.9）、研判路径标签"⚡ 预筛直达（确定性规则）"
   - **事件类型**：恶意脚本执行；**风险等级**：critical

**讲解词**：
> 这个事件包含 EncodedCommand 编码命令特征，命中确定性预筛的攻击规则，毫秒级直接定级为 critical，没有调用大模型——这就是"规则先筛"的价值：明确攻击不浪费 LLM 调用。

---

### 第四节（3:00-4:30）：案例 2——误报（EVENT-002）

**讲解词**：
> 第二个案例是典型的误报：打印机服务器的白名单扫描活动。

**操作**：
1. 点击 **EVENT-002（打印机服务器 whitelist 扫描活动）**
2. 观察结果区：
   - **研判路径**：预筛直达；**风险等级**：low；**疑似误报**：是
   - **决策可视化**：置信度 high（0.9）

**讲解词**：
> 这个事件命中白名单资产、存在变更单、行为是例行扫描，预筛器直接判定误报并自动关闭，同样不调 LLM。误报自动剔除，正是降低告警噪音的关键能力。

---

### 第五节（4:30-6:00）：案例 3——待确认（EVENT-003）

**讲解词**：
> 第三个案例是证据不足的异常外联：OA 服务器对外发起可疑连接。这类灰色地带事件，预筛器不会武断，而是交给 LLM 深度研判。

**操作**：
1. 点击 **EVENT-003（OA 服务器异常外联）**
2. 观察结果区：
   - **研判路径**：🤖 LLM 深度研判；**事件类型**：异常外联；**风险等级**：high
   - **推理摘要**：展示 LLM 的推理依据（含 ATT&CK 技术引用）
   - **知识命中**：展示命中的 ATT&CK/CVE 依据（如 T1071 应用层协议）
3. 若置信度 low：展示 **"待人工复核"横幅** + 确认/驳回按钮
4. 点击"驳回（判定误报）"，输入意见，提交后刷新显示"已人工驳回"

**讲解词**：
> 对不确定的事件，LLM 综合情报库、知识库和攻击特征做深度研判，输出结构化裁决。如果置信度低，结果不会自动处置，而是进入人工复核环节——AI 决策、人工兜底，这就是 HITL 闭环。同时注意知识命中区显示了 ATT&CK 技术映射，这是用知识库做 grounding，减少大模型幻觉。

---

### 第六节（6:00-7:30）：三模式对比 + 混淆矩阵（核心数据）

**操作**：
1. 在评测面板点击 **"生成三模式对比"**（首次需 1-2 分钟真实 LLM 评测，建议提前生成）
2. 观察纯 CSS 柱状图：纯规则 / 纯 LLM / 预筛+LLM 混合 三模式的通过率条形图
3. 观察混淆矩阵（2×2）：TP/FN/FP/TN 颜色编码
4. 指向指标：混合模式通过率最高、成本最低、LLM 调用次数最少

**讲解词**：
> 我们做了三模式对比：纯规则引擎准确率低；纯 LLM 成本高、慢；而预筛+LLM 混合模式准确率最高、成本最低。这套混淆矩阵直接证明混合架构的有效性——TP（真正识别的误报）最高，FP（误伤）最低。评测报告还可以一键导出为 Markdown/HTML，包含混淆矩阵和逐案例明细。

---

### 第七节（7:30-8:30）：审计回放

**操作**：
1. 点击首页顶部 **"审计回放"** 按钮
2. 在审计页选择 **EVENT-001**（或刚才演示的事件）
3. 展示调查过程时间线：context（工具调用）→ prefilter → triage → postprocess，每步含时间戳
4. 展开 LLM 调用记录：完整 prompt + response
5. 点击 **"导出 JSON"**：完整证据链可核查

**讲解词**：
> 每次研判都会生成一份完整的审计账本（Investigation Ledger）：工具调用、LLM 的 prompt 和响应、最终裁决，全部记录可回放、可导出。评委可以逐条核查我们的决策过程，这就是可审计、可复现。

---

### 第八节（8:30-9:30）：创新点总结

**讲解词**（对照 PPT）：
> 我们总结五个核心创新点：
> 1. **预筛+LLM 混合架构**：规则先筛、不确定才给 LLM，节省 70% LLM 调用
> 2. **置信度门控 + HITL**：低置信不自动处置，人工复核回写形成闭环
> 3. **多 Agent 顺序协作**：Triage → Hunt → Respond → Report，体现自主决策
> 4. **误报记忆与持续学习**：相似历史注入 prompt，同类误报不重复出现
> 5. **全链路审计账本**：证据链完整可回放，评审可核查
