## 二、答辩增强点（P0 必做）

### P0-1：准备一份"三模式对比"核心数据图
- **现状**：`evaluate_modes()` 输出 JSON，但无可视化
- **增强**：在 Web 大屏加一张**三模式对比柱状图**（纯 CSS/HTML，无需 JS 库）
- **数据**：纯规则（~0.1）vs 纯 LLM（~0.6）vs 混合（0.9）的通过率 + 成本 + 耗时
- **答辩价值**：评委一眼看懂"为什么混合架构最优"

### P0-2：补一份"混淆矩阵"
- **现状**：`evaluation/service.py` 有 `_confusion_markdown()` 但 Web 未展示
- **增强**：在评测面板加混淆矩阵 2×2 表格（TP/FN/FP/TN）
- **答辩价值**：体现"误报识别能力"的专业度

### P0-3：写一份 10 分钟演示脚本
- **内容**：痛点（30s）→ 方案（90s）→ 演示 3 个案例（3min）→ 三模式对比数据（2min）→ 创新点（1min）→ 总结（30s）
- **演示案例**：EVENT-001（攻击，预筛直达）/ EVENT-002（误报，自动关闭）/ EVENT-003（待确认，LLM 深判 + HITL）

### P0-4：准备"一句话定位"
> *"唯一用三模式对比评测证明混合架构最优的安全研判 Agent——预筛省 70% LLM 调用，误报记忆让同类误报不重复，全链路审计可回放。"*

## 四、与竞品差异化（57 件 LLM+Agent+安全三重交叉）

| 竞品做法 | 我的项目差异 | 优势 |
|---------|------------|------|
| `AgentGuard` 系列做"行为监督" | 我做"预筛 + 研判 + 门控 + 记忆 + 审计"全链路 | 更深的工程化（10 阶段 vs 单点） |
| `LLM 驱动的可信安全运营智能体`（N0T） | 我有三模式对比评测数据 | 用数据证明架构价值，不是空谈 |
| `MCP-Sentinel` 做"工具调用护栏" | 我做"事件研判 + 多 Agent 协作 + Ledger 审计" | 更完整的安全运营闭环 |
| `DeepShield` 做"越狱检测 + 工具审计" | 我有误报记忆 + 置信度校准 | 更贴合真实 SOC 场景 |
| 多数作品无真实评测 | 我有 10 脚本 208/208 + 混淆矩阵 + 成本估算 | 量化可验证，评委可打分 |

**核心卖点**：**"预筛省 70% + 三模式对比证明 + 误报记忆 + 全链路审计"**
